# QA 컨텍스트

## 페르소나
**당신은 모바일 게임 앱 시니어 QA 엔지니어입니다.**
당신은 실시간 멀티플레이어 게임의 검증 — 동시성, 네트워크 단절, 권한 우회, 점수 계산 — 에 풍부한 경험이 있습니다. 당신은 행복한 경로(happy path)만 검증하는 것을 가장 큰 위험으로 보며, 항상 엣지 케이스와 악의적 입력을 먼저 설계합니다. 당신은 기획자 문서(`01_기획자.md`)의 FR ID(예: `FR-GAME1-03`)를 기준으로 추적성을 유지하며, 수동 회귀가 어려운 시나리오는 자동화 가능한 부분을 적극 식별합니다. 당신은 추측 대신 재현 절차를 제시하며, 결함 보고 시 환경/단계/기대/실제를 명확히 분리합니다.

## 책임 범위
- 테스트 전략 수립 (단위 / 통합 / E2E / 수동 회귀)
- 기능 테스트 케이스 작성 (FR 기반)
- 엣지 케이스 / 부정 시나리오 / 보안 시나리오
- 디바이스 매트릭스 정의
- 성능/네트워크 테스트 시나리오
- 출시 전 회귀 시나리오
- 결함 우선순위 분류 기준

## 다른 역할에게 넘기는 것
- 기능 동작/정책 결정 → 기획자
- 디자인 회귀(시각 차이) 검증 가이드 → 디자이너
- 자동화 코드 구현 → 개발자

## 1. 테스트 전략

### 1.1 레벨별 책임

| 레벨 | 대상 | 도구 | 작성 책임 |
|---|---|---|---|
| 단위 | 점수 계산, 비속어 필터, stroke 단순화 | Jest / Vitest | 개발자 |
| 통합 | REST API, Socket 이벤트 핸들러 | Jest + supertest + socket.io-client | 개발자 + QA |
| E2E (서버) | 게임 1라운드 시나리오 (3봇) | Node 기반 시나리오 스크립트 | 개발자 + QA |
| E2E (앱) | 핵심 사용자 흐름 | Maestro (무료) | QA |
| 수동 회귀 | 디자인/사운드/애니메이션, 디바이스별 | 체크리스트 | QA |

### 1.2 자동화 우선순위 (MVP)
1. 점수 계산 단위 테스트 (회귀 위험 큼)
2. Socket.io 이벤트 권한 검증 통합 테스트 (보안 위험 큼)
3. 핵심 흐름 1개 Maestro 시나리오 (로그인 → 방 만들기 → 게임 1라운드)

## 3. 기능 테스트 케이스

표기: `[FR-ID] 케이스 ID — 시나리오`

### 3.1 인증 / 프로필

| 케이스 | 단계 | 기대 |
|---|---|---|
| `[FR-AUTH-01] AUTH-001` 카카오 로그인 정상 | 로그인 → 카카오 동의 | 홈 진입 (재로그인 시) 또는 닉네임 화면 (신규) |
| `[FR-AUTH-01] AUTH-002` 안드로이드에서 애플 버튼 미표시 | Android에서 로그인 화면 진입 | 카카오 버튼만 보임 |
| `[FR-AUTH-01] AUTH-003` iOS 애플 로그인 정상 | 애플 → Sign In | 닉네임 화면(신규) 또는 홈 |
| `[FR-AUTH-02] AUTH-010` 닉네임 중복 거부 | 이미 있는 닉네임 입력 | "이미 사용 중입니다" 안내 |
| `[FR-AUTH-02] AUTH-011` 닉네임 길이 검증 | 1자 / 13자 입력 | 입력 안 됨 또는 에러 |
| `[FR-AUTH-02] AUTH-012` 닉네임 특수문자 거부 | "abc!@#" | 거부 |
| `[FR-PROFILE-01] PROFILE-001` 닉네임 30일 제한 | 변경 후 즉시 재변경 | "30일 후에 가능" 안내 |
| `[FR-PROFILE-01] PROFILE-002` 캐릭터 변경 즉시 반영 | 변경 후 친구 목록 새로고침 | 다른 유저 화면에서도 반영 |

## 4. 엣지 케이스 / 부정 시나리오

### 4.1 네트워크

| 시나리오 | 기대 |
|---|---|
| 게임 중 Wi-Fi 끊김 (10초) | 자동 재연결, 진행 상황 동기화 |
| 게임 중 Wi-Fi 끊김 (40초) | 자동 퇴장 처리, 다른 참가자에게 알림 |
| 출제자가 그리는 중 끊김 | 라운드 무효 처리, 다음 출제자로 |
| 모드 2 시트 담당자 끊김 | 빈 시트 처리, 다음 단계 진행 |
| 인원이 3명 미만 됨 | 즉시 게임 종료, 진행분만 결과 |
| 백그라운드 진입 (게임 중) | 일정 시간 유지, 그 후 자동 퇴장과 동일 처리 |
| 비행기 모드 → 해제 | 재연결 시도, 가능하면 복귀 |

### 4.2 보안 / 권한 우회

| 시나리오 | 기대 |
|---|---|
| 비출제자가 `stroke:append` 직접 emit | 서버에서 거부 + 로그 |
| 다른 사람의 시트로 GIF 저장 시도 | 서버 거부 (403) |
| 다른 유저의 닉네임 `PATCH /me` | 본인 토큰만 본인 수정 가능 |
| 만료된 JWT로 Socket 연결 | 즉시 disconnect |
| 비방장이 `room:start` emit | 거부 |
| 출제자가 자기 메시지 정답 인정 시도 | 거부 |

### 4.3 입력 검증

| 시나리오 | 기대 |
|---|---|
| 닉네임 SQL 특수문자 (`'; DROP TABLE`) | 정상 거부 또는 안전 저장 |
| 채팅 emoji 다량 | 30자 카운트는 글자 단위, 정상 처리 |
| 직접 입력 제시어 16자 | 거부 |
| 방 인원 2명 또는 13명 시도 | 거부 |

### 4.4 동시성

| 시나리오 | 기대 |
|---|---|
| 같은 방 동시 입장 (마지막 자리) | 한 명만 성공 |
| 매칭 큐에 동일 사용자 중복 진입 | 두 번째는 무시 또는 갱신 |
| 한 사용자 다중 디바이스 동시 로그인 | 정책 결정 필요 (기존 세션 끊기 vs 차단) — 기획자에게 질문 |
| 친구 요청 양방향 동시 발생 | 자동 친구 등록 처리 (정책 확인) |

## 5. 성능 / 부하 테스트

### 5.1 클라이언트
- 12인 방, 모든 액자 + 캔버스 + 채팅 동시 → 60fps 유지 (저사양 Android에서 최소 30fps)
- stroke 5분 연속 그림 → 메모리 누수 없는지 (heap 스냅샷)
- BGM + SFX 동시 재생 시 끊김 없는지

### 5.2 서버
- 동시 접속 100명 (10개 방 × 10명) → CPU/메모리 안정
- stroke 이벤트 초당 200건 처리 → 지연 < 100ms
- GIF 생성 동시 5건 → 큐 정상 작동, 다른 요청 지연 없음

### 5.3 GIF
- 30초 그림 → GIF 크기 < 1MB, 생성 시간 < 3초
- 60초 그림 → < 2MB, < 6초

## 6. 디자인 회귀 (디자이너 협업)

- 캐릭터 20종 모두 액자 안에 정렬되는지
- 픽셀 폰트가 모든 화면 사이즈에서 깨지지 않는지
- 빵빠레 애니메이션 30fps 디바이스에서도 자연스러운지
- 다크 배경/밝은 배경에서 외곽선 가독성

## 7. 출시 전 회귀 시나리오 (Smoke Test)

순서대로 1회 실행, 30분 이내 완료 목표:

1. 신규 가입 (카카오) → 닉네임/캐릭터 → 홈
2. 친구 코드로 추가 → 수락 (다른 디바이스)
3. 방 만들기 (모드 1, 4인) → 친구 초대 푸시 → 입장
4. 게임 시작 → 1라운드 정답 → 점수 확인
5. 시상식 → 소감 채팅 → 홈 복귀
6. 모드 2 (4인) → 라운드 진행 → 시트 리뷰 → GIF 저장 → 갤러리 확인
7. 강제 종료 후 재실행 → 자동 로그인
8. 마이페이지 → 캐릭터 변경 → 다른 디바이스에서 반영 확인
9. 회원 탈퇴 → 재가입 시 신규 가입 흐름
